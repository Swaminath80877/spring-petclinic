# Feature Specification: Owner Management

**Feature Branch**: `002-owners-spring-petclinic`

**Created**: 2026-03-19

**Status**: Draft

**Input**: User description: "owners for spring-petclinic"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Find Owners by Last Name (Priority: P1)

**Description**: As a clinic staff member, I want to search for owners by their last name so that I can quickly access their information.

**Why this priority**: This is a core functionality for managing owners and is essential for daily operations.

**Independent Test**: Can be fully tested by entering a last name prefix in the search bar and verifying the returned list of owners. Delivers the ability to locate specific owners.

**Acceptance Scenarios**:

1. **Given** a list of owners exists, **When** a user searches for owners by the last name prefix "Sm", **Then** a list of owners whose last names start with "Sm" (e.g., Smith, Smothers) is displayed.
2. **Given** no owners match the search prefix, **When** a user searches for owners by the last name prefix "XYZ", **Then** a message indicating "No owners found" is displayed.

---

### User Story 2 - Create a New Owner (Priority: P1)

**Description**: As a clinic staff member, I want to create a new owner record so that I can register new clients and their pets.

**Why this priority**: Essential for onboarding new clients into the system.

**Independent Test**: Can be fully tested by filling out the new owner form with valid data and submitting it. Delivers the ability to add new clients.

**Acceptance Scenarios**:

1. **Given** a user is on the new owner form, **When** they submit a valid owner form with all required fields filled, **Then** the owner is created and redirected to the owner's details page.
2. **Given** a user is on the new owner form, **When** they submit the form with a blank address, **Then** a validation error message is displayed for the address field, and the owner is not created.

---

### User Story 3 - View Owner List (Priority: P2)

**Description**: As a clinic staff member, I want to view a list of all owners so that I can get an overview of registered clients.

**Why this priority**: Provides a general overview and is useful for navigation.

**Independent Test**: Can be fully tested by navigating to the owners list page. Delivers a comprehensive view of all registered owners.

**Acceptance Scenarios**:

1. **Given** a user navigates to the owners list page, **When** the page loads, **Then** a list of all registered owners is displayed, including their first name, last name, address, and telephone number.

---

### User Story 4 - Update Owner Information (Priority: P2)

**Description**: As a clinic staff member, I want to update an existing owner's information so that I can keep client records accurate.

**Why this priority**: Important for maintaining data integrity.

**Independent Test**: Can be fully tested by selecting an owner, modifying their details, and saving the changes. Delivers the ability to correct or update owner data.

**Acceptance Scenarios**:

1. **Given** an existing owner's details are displayed, **When** the user modifies the owner's telephone number and saves, **Then** the owner's telephone number is updated in the system.
2. **Given** an existing owner's details are displayed, **When** the user attempts to save with an invalid telephone format, **Then** a validation error is shown, and the changes are not saved.

---

### User Story 5 - Add a New Pet to an Owner (Priority: P1)

**Description**: As a clinic staff member, I want to add a new pet to an existing owner's record so that I can track their animals.

**Why this priority**: Core functionality for managing a pet owner's animals.

**Independent Test**: Can be fully tested by selecting an owner, navigating to the add pet form, filling it with valid data, and saving. Delivers the ability to associate pets with owners.

**Acceptance Scenarios**:

1. **Given** an owner's details are displayed, **When** the user adds a new pet with a valid name and type, **Then** the new pet is associated with the owner.
2. **Given** an owner's details are displayed, **When** the user attempts to add a pet with a blank name, **Then** a validation error is displayed for the pet's name.

---

### User Story 6 - View and Add Visits for a Pet (Priority: P1)

**Description**: As a clinic staff member, I want to view and add visits for a pet so that I can maintain a history of their medical care.

**Why this priority**: Crucial for tracking pet health and treatment history.

**Independent Test**: Can be fully tested by selecting a pet, viewing its existing visits, and adding a new visit with a valid date. Delivers the ability to manage pet visit records.

**Acceptance Scenarios**:

1. **Given** a pet has existing visits, **When** the user views the pet's details, **Then** a list of past visits is displayed.
2. **Given** a pet's details are displayed, **When** the user adds a new visit with a valid date, **Then** the new visit is recorded for the pet.

---

### Edge Cases

- **Blank Address**: Owner creation/update with a blank address → validation error.
- **Blank City**: Owner creation/update with a blank city → validation error.
- **Invalid Telephone Format**: Owner creation/update with a telephone number not matching the "\\d{10}" pattern → validation error.
- **Blank Owner Last Name**: Owner search with a blank last name → returns all owners.
- **Non-existent Owner ID**: Accessing an owner with an ID that does not exist → `IllegalArgumentException` is thrown.
- **Blank Pet Name**: Pet creation/update with a blank name → validation error.
- **Missing Pet Type**: Pet creation with a missing pet type → validation error.
- **Invalid Pet Birth Date**: Pet creation/update with a null birth date → validation error.
- **Duplicate Pet Name for Same Owner**: Attempting to add a pet with a name that already exists for the same owner → validation error.
- **Invalid Visit Date**: Visit creation with a date that is not after the current date → validation error.
- **Non-existent Owner ID for Visit**: Attempting to add a visit for an owner ID that does not exist → `IllegalArgumentException` is thrown.
- **Non-existent Pet ID for Visit**: Attempting to add a visit for a pet ID that does not exist for a given owner → `IllegalArgumentException` is thrown.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow the creation of a new owner.
- **FR-002**: System MUST allow updating an existing owner's information (address, city, telephone).
- **FR-003**: System MUST allow searching for owners by last name prefix.
- **FR-004**: System MUST display a list of all owners.
- **FR-005**: System MUST allow the creation of a new pet for a given owner.
- **FR-006**: System MUST allow updating an existing pet's name.
- **FR-007**: System MUST allow viewing existing visits for a pet.
- **FR-008**: System MUST allow adding a new visit for a pet.
- **FR-009**: System SHOULD validate owner information during creation or update (address, city, telephone format).
- **FR-010**: System SHOULD validate pet information during creation or update (name, type, birth date).
- **FR-011**: System SHOULD validate visit information during creation (date).
- **FR-012**: System SHOULD display a form for creating or updating owner details.
- **FR-013**: System SHOULD display a form for creating or updating pet details.
- **FR-014**: System SHOULD display a form for adding a visit.
- **FR-015**: System SHOULD allow fetching an owner by their last name.

### Key Entities *(include if feature involves data)*

- **Owner**: Represents a client of the veterinary clinic. Includes first name, last name, address, city, and telephone number. Can have multiple pets.
- **Pet**: Represents an animal belonging to an owner. Includes name, birth date, and type. Can have multiple visits.
- **PetType**: Represents the species of a pet (e.g., Cat, Dog).
- **Visit**: Represents a medical visit for a pet. Includes date.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can find owners by last name prefix in under 2 seconds.
- **SC-002**: New owner creation and redirection to their details page completes in under 3 seconds.
- **SC-003**: 95% of users can successfully add a new pet to an owner on their first attempt.
- **SC-004**: The system supports displaying a list of up to 100 owners without significant performance degradation.
- **SC-005**: All validation errors for owner and pet creation/updates are displayed clearly to the user.
